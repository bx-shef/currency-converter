## 1. Что это

Конвертер валют по официальному курсу НБ РБ. **Статика (Nuxt 4 SSG)** — своего сервера,
базы данных и логов нет.

Работает в двух режимах:

- **обычный сайт** (standalone) — калькулятор, сумма прописью, формула, промо-блок;
- **приложение внутри портала Bitrix24** (iframe) — виджет в панели над полем ввода чата
  («Вставить в чат») плюс главная, которая может открыться как приложение портала.

Стек: Nuxt 4, Vue 3 (`<script setup lang="ts">`), строгий TypeScript, Tailwind CSS v4,
Bitrix24 UI (`b24ui`), `@bitrix24/b24jssdk`, `@nuxtjs/i18n`, Vitest.

Бандл держим **как есть**, чтобы синхронизировать с источником: у него свои конвенции и свой

Что важно знать, чтобы не сломать:

- **Внутри бандла лежит своя `docs/project-map.md`** — это копия шаблона, а не карта нашего
  проекта. Источник правды — файл, который вы читаете сейчас; та копия может расходиться
  с реальностью.
- **При обновлении бандла из источника** (`cp -a`) обязательно **вернуть из git** файлы
  `reporting-kit/docs/project-map.md` и `reporting-kit/CLAUDE.md` — иначе шаблон затрёт
  данные проекта. Улучшения самого бандла отправляем в источник, а не правим здесь.
- **GitHub не запускает workflow из `reporting-kit/.github/`** — активны только те, что
  лежат в корневом `.github/`. Не принимайте «зелёный CI бандла» за настоящий.
- **Токен Telegram** держим только локально в `.env` с правами `600`, в CI — через
  переменные окружения. Скрипт отправки не передаёт токен аргументом командной строки,
  чтобы он не светился в списке процессов.

## 4. Данные и приватность

Это раздел, на который ссылается гейт публикации в Маркете — здесь ответы на вопросы
«какие данные вы собираете» и «что храните».

**Главное правило: наружу уходит только факт события или диапазон, никогда сами значения.**
Суммы, курсы и то, что человек ввёл, не отправляются никуда.

### Что покидает браузер

| Куда | Что | Данные пользователя? |
|---|---|---|
| `api.nbrb.by` (`GET exrates/rates`) | публичные курсы НБ РБ | Нет — только читаем |
| Яндекс.Метрика (`mc.yandex.ru/metrika/tag.js`) — **только на обычном сайте** | обезличенная аналитика и цели из таблицы ниже | Нет значений и ввода |

Больше исходящих каналов нет: своего сервера у приложения не существует.

Метрика включена с картой кликов, отслеживанием переходов по ссылкам и точным показателем
отказов. Это её **встроенные** функции: они работают по политике Яндекса и находятся вне
нашего правила «только факт события» — но данные приложения (суммы, курсы, ввод) в них тоже
не попадают. Метрика ставит **свои** cookies.

### Что хранится в браузере и никуда не уходит

| Что | Ключ | Срок |
|---|---|---|
| Кэш курсов | `nbrb_rates_v2` (localStorage) | 12 часов |
| Факт ответа на 👍/👎 — чтобы не спрашивать повторно | `converter_helpful_v1` (localStorage) | бессрочно |
| Выбранная тема | `vueuse-color-scheme` (localStorage) | бессрочно |
| Выбранный язык — наша собственная cookie | `i18n_redirected` (cookie) | бессрочно |

Суммы и ввод пользователя не сохраняются нигде.

### Цели Метрики (только на обычном сайте)

| Цель | Когда срабатывает | Откуда шлётся |
|---|---|---|
| `rates_load_failed` | сбой загрузки основной (дневной) ленты курсов | `useNbrbRates` |
| `rates_monthly_missing` | дневная лента пришла, месячная упала | `useNbrbRates` |
| `rates_fallback_used` | первая загрузка не удалась, показана резервная копия | `useNbrbRates` |
| `converter_helpful_yes` / `_no` | клик 👍 или 👎 в блоке «Помог курс?» | `index.vue` |
| `market_card_click` | клик по кнопке карточки «Приложение для Bitrix24» | `AppInBitrixCard` |
| `market_qr_reveal` | показ QR листинга Маркета | `HoldRevealQr` |
| `custom_dev_click` | клик по кнопке карточки «Нужна доработка…» | `CustomDevCard` |
| `custom_dev_qr_reveal` | показ QR предложения о доработке | `HoldRevealQr` |
| `web_vitals_<lcp\|cls\|inp>_<good\|ni\|poor>` | замер скорости страницы — **диапазон**, не миллисекунды | `webVitals.client.ts` |

### Внутри портала Bitrix24 статистики нет вообще

Защита двойная, чтобы это не сломалось случайно:

1. `public/metrika.js` глушит сам себя, если страница открыта во фрейме — Метрика не
   инициализируется, её объект в окне вообще не появляется;
2. плагин замеров скорости отдельно проверяет признак «мы во фрейме»
   (`app/utils/isEmbedded.ts`) — в портале библиотека замеров даже не загружается; а любая
   отправка цели без загруженной Метрики просто ничего не делает.

Пользователей портала мы не отслеживаем осознанно, а не по случайности.

### Чего нет

Своего сервера, базы данных, логов действий пользователя; отправки сумм, курсов и ввода
куда бы то ни было; сторонних скриптов кроме Яндекс.Метрики (и только на обычном сайте).
Собственная cookie ровно одна — `i18n_redirected` для запоминания языка.

## 5. Решено и отклонено

Память, чтобы уже отвергнутое не предлагалось заново.

**Главное свойство проекта — работать без серверной части.** Рассматривались три уровня:
**A. только статика** (текущий — всё выше сделано так) → **B. плюс одна облачная функция**
(сбор отзывов) → **C. плюс полноценный сервер** (очереди, серверная статистика). B и C
намеренно ломают это свойство, поэтому берутся **только под конкретный спрос и по решению
владельца**, а не по умолчанию.

**Явно не берём** как неприменимое к статике: очереди и брокеры сообщений, база данных,
пул фоновых обработчиков, хранилище токенов, AI-агент внутри приложения, защитный слой на
периферии (у нас эту роль играет nginx), ролевые инструкции (ролей в приложении нет).

**Отклонено осознанно:**

- **Ещё одна просьба оценить приложение в Маркете** — на странице уже есть 👍/👎 и две
  промо-карточки; третий призыв — перебор, он мешает основному делу.
- **Отдельная форма для свободного отзыва** — канал уже есть: карточка доработки ведёт на
  бриф, плюс сигнал 👍/👎. Плодить ещё одну форму не нужно.
