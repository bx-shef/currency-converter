## 1. Что это

Конвертер валют по официальному курсу НБ РБ. **Статика (Nuxt 4 SSG)** — своего сервера,
базы данных и логов нет.

Работает в двух режимах:

- **обычный сайт** (standalone) — калькулятор, сумма прописью, формула, промо-блок;
- **приложение внутри портала Bitrix24** (iframe) — виджет в панели над полем ввода чата
  («Вставить в чат») плюс главная, которая может открыться как приложение портала.

Стек: Nuxt 4, Vue 3 (`<script setup lang="ts">`), строгий TypeScript, Tailwind CSS v4,
Bitrix24 UI (`b24ui`), `@bitrix24/b24jssdk`, `@nuxtjs/i18n`, Vitest.

## 4. Данные и приватность

**Инвариант: «shape/outcome, never content»** — наружу уходит только факт или бакет события,
никогда сами значения (суммы, курсы, ввод пользователя).

**Что покидает браузер:**

| Куда | Что | Данные пользователя? |
|---|---|---|
| `api.nbrb.by` | публичные курсы НБ РБ | Нет — только читаем |
| Яндекс.Метрика, **только standalone** | обезличенная аналитика + цели ниже | Нет значений и ввода |

Больше исходящих каналов нет: своего API у приложения не существует. Метрика инициализируется
с картой кликов, трекингом ссылок и точным показателем отказов — это её встроенные функции,
работающие по её собственной политике, и ставит она свои cookies. Внутри портала Bitrix24
Метрика **не грузится вовсе**, поэтому пользователей портала мы не трекаем by design.

**Что хранится локально** (и никуда не уходит): кэш курсов `nbrb_rates_v2` (12 ч), факт
ответа на 👍/👎 `converter_helpful_v1`, выбранная тема `vueuse-color-scheme`. Суммы и ввод
в хранилище не попадают.

**Цели Метрики** (только standalone): `rates_load_failed` · `rates_monthly_missing` ·
`rates_fallback_used` · `converter_helpful_yes` / `_no` · `market_card_click` ·
`market_qr_reveal` · `custom_dev_click` · `custom_dev_qr_reveal` ·
`web_vitals_<lcp|cls|inp>_<good|ni|poor>`.

**Чего нет:** своего сервера, базы, логов действий; отправки сумм, курсов и ввода куда бы то
ни было; сторонних скриптов кроме Метрики; собственных cookies.

## 5. Решено и отклонено

Память, чтобы уже отвергнутое не предлагалось заново.

**Инвариант проекта — без серверной части.** Рассматривались уровни развития:
**A. статикой** (текущий, всё выше сделано так) → **B. + одна serverless-функция** (сбор
фидбэка) → **C. + сервер** (очереди, серверная телеметрия). B и C намеренно ломают инвариант,
поэтому берутся **только под конкретный спрос и по решению владельца**, не по умолчанию.

**Явно не берём** как неприменимое к статике: очереди и брокеры, база данных, пул воркеров,
хранилище токенов, AI-агент в рантайме, edge-security middleware (у нас nginx), ролевые
руководства (ролей нет).

**Отклонено осознанно:**

- **Ещё один nudge с просьбой оценить в Маркете** — на странице уже есть 👍/👎 и две
  промо-карточки; третий призыв = пере-наджинг, вредит основному сценарию.
- **Отдельная форма свободного фидбэка** — канал уже есть: карточка доработки ведёт на бриф,
  плюс сигнал 👍/👎. Плодить форму или `mailto` не нужно.
