## Инструменты

Все — только чтение, без данных портала и без токенов портала. Ответ — JSON для модели с полем `say` (как пересказать).

| Имя | Что | Аргументы |
|---|---|---|
| `rates` | официальные курсы на дату: BYN за `scale` единиц валюты | `date` (ГГГГ-ММ-ДД, нет — сегодня по Минску), `codes` (до 20; нет — USD, EUR, RUB, CNY, KZT, PLN) |
| `history` | курс одной валюты по дням за период, изменение, минимум, максимум | `code`, `from`, `to` (нет — сегодня); до 366 дней |
| `convert` | пересчёт суммы через BYN по курсу на дату: итог, курсы, дата | `amount` (0 … 10¹²), `from`, `to`, `date` |
| `sum_in_words` | сумма прописью для BYN и RUB, как в платёжке: «Сто двадцать три рубля 45 копеек» | `amount`, `currency` (`BYN`, `RUB`) |

- Курс — дневной фид НБ РБ; валюты, которые НБ РБ устанавливает только помесячно (RSD), берутся из месячного
  (`periodicity: monthly` в ответе).
- Дата — не позже завтрашней: НБ РБ публикует курс на завтра днём. Будущая дата и чужой формат — отказ `bad_args`.
- Копейки округляются только через `toKopecks` (`app/utils/formatters.ts`) — те же функции, что у экрана и прописи
  на сайте, второй копии логики сумм нет.
- НБ РБ не ответил — отказ `rates_unavailable` («повторите через минуту»), курс не подставляется.
- В описании каждого инструмента: «курсы портала — встроенным инструментом курсов портала (`crm_currency`); официальный
  курс НБ РБ — этим; в интернете не искать».

## Ключ подключения — по порталу, а не по `member_id`

`member_id` не уникален среди всех Битрикс24: коробки, развёрнутые из одного образа, могут его совпадать
(bx-shef/toolsai-mcp #243). Поэтому ключ хранится по паре **`member_id` + хост портала** (`mcpkey:<member_id>:<хост>`,
хост — нижний регистр, без `www` и порта), до 8 порталов на один `member_id`. Выпуск или отзыв ключа на одном портале
не трогает другой.

Протокол передаёт в заголовке только `X-Shef-Member`, поэтому запрос проверяется каждым ключом этого `member_id` за
постоянное время (без досрочного выхода); подошедший ключ даёт хост, и `who.host` из подписанного тела обязан с ним
совпасть — иначе `401 host_mismatch`. Заголовок с хостом в протоколе — bx-shef/toolsai-mcp #304.

Ключ зашифрован AES-256-GCM (ключ — HKDF от `ENCRYPTION_KEY`), внутри шифротекста — `member_id` и хост: запись,
перенесённая под имя другого портала, не читается.

## Проверка запроса

1. Ключи по `X-Shef-Member`; нет ни одного — `401`.
2. `HMAC-SHA256(ключ, ts + "." + сырое тело)` против `X-Shef-Signature`, каждым ключом; не подошёл ни один — `401`.
3. `|сейчас − ts| ≤ 300` — иначе `401`.
4. Тело: `ts` и `who.member_id` равны заголовкам, `who.host` — хосту ключа; `nonce` не встречался 10 минут — иначе `409`.

Контрольные значения подписи протокола сверяет `tests/mcpProtocol.test.ts`.

## Проверено мутациями

Каждая поломка ниже краснит тесты: ключ только по `member_id`, без сверки хоста, без окна времени, без одноразового
номера, запись не привязана к хосту, копейки в обход `toKopecks`, курс на будущую дату.
