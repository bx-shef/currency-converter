# Процесс: от настройки до публикации в Bitrix24

> Last reviewed: 2026-07-29

Один сквозной документ: как приложение настраивается, разрабатывается, проверяется,
попадает на прод, устанавливается в портал Bitrix24 и публикуется в Маркете. Дальше —
как это эксплуатировать и что делать, когда сломалось.

**Соседние документы:** [`PROJECT_MAP.md`](PROJECT_MAP.md) — что в проекте есть и в каком
статусе · [`FUTURE.md`](FUTURE.md) — что делаем потом · [`../CLAUDE.md`](../CLAUDE.md) —
архитектура и конвенции кода · [`../README.md`](../README.md) — инструкция пользователю.

**Весь путь одной схемой:**

```
0. Настройка (один раз)
     ↓
1. Разработка: ветка → правка → pnpm check
     ↓
2. Проверка: авто (CI) + глазами (screenshots) + руками (портал)
     ↓
3. PR → проверяющие → зелёный CI → squash-мерж в main
     ↓
4. Деплой: CI собирает образ → GHCR → Watchtower → прод за nginx-proxy
     ↓
5. Установка в портал Bitrix24: /install → placement.bind → виджет в чате
     ↓
6. Публикация в Маркете Bitrix24 (гейты)
     ↓
7. Эксплуатация: мониторинг, откат, инциденты
```

---

## 0. Настройка — что задать один раз

### 0.1. Переменные приложения

Все публичные переменные **запекаются в бандл при сборке** (SSG), поэтому передаются
build-арг’ами в Docker, а **не** через `environment:` в compose. Задаются в
`.github/workflows/ci.yml` → `Dockerfile` (`ARG`/`ENV`) → `nuxt.config.ts` (`runtimeConfig.public`).

| Переменная | Зачем | Обязательна |
|---|---|---|
| `NUXT_PUBLIC_SITE_URL` | абсолютный адрес сайта; из него строится HANDLER плейсмента при установке в портал | **Да** для прода — иначе в портал запишется битый относительный URL |
| `NUXT_PUBLIC_YANDEX_COUNTER_ID` | счётчик Яндекс.Метрики | Нет (пусто → вся телеметрия no-op) |
| `NUXT_PUBLIC_COMMIT_SHA` | коммит сборки, показывается в подвале ссылкой | Нет (пусто → «сборка dev») |
| `NUXT_PUBLIC_MARKETPLACE_URL` | ссылка на листинг Маркета в промо-карточке | Нет (пусто → константа `MARKETPLACE_URL` из `app/utils/site.ts`) |
| `NUXT_PUBLIC_AUTHOR_NAME` / `_URL` | автор в подвале | Нет |

Сборка **падает специально**, если `NUXT_PUBLIC_YANDEX_COUNTER_ID` задан, но это не число —
чтобы битый id не запёкся в бандл.

### 0.2. Что должно быть готово на сервере

```
/home/<user>/<project>/
├── docker-compose.prod.yml
├── docker-compose.nginxproxy.yml   # только если nginx-proxy ещё не развёрнут
├── .env.prod                        # НЕ в git: DOMAIN, LETSENCRYPT_EMAIL
└── Makefile
```

**Git на сервер не клонируется** — файлы качаются напрямую:

```bash
mkdir -p /home/<user>/<project> && cd $_
BASE="https://raw.githubusercontent.com/bx-shef/currency-converter/main"
for f in docker-compose.prod.yml Makefile .env.prod.example; do curl -fsSLO "$BASE/$f"; done
cp .env.prod.example .env.prod && nano .env.prod
```

Обновление файлов на сервере — тем же `curl -fsSLO`, без `git pull`.

Чек-лист первого запуска:

- [ ] DNS A-запись домена указывает на сервер (`dig +short <домен>`) — **до** первого старта
      acme-companion, иначе Let's Encrypt закеширует rate-limit на час
- [ ] docker-сеть nginx-proxy существует и её имя совпадает с указанным в compose
      (`docker network ls`) — имя историческое и на разных серверах разное
- [ ] nginx-proxy запущен (`docker ps | grep nginx-proxy`); если впервые — `make init-nginxproxy`
- [ ] `.env.prod` заполнен
- [ ] `make prod-up` отработал; `docker ps` показывает приложение **и** Watchtower
- [ ] `curl -I https://<домен>` → `200`, TLS валиден

## 1. Разработка

```
ветка от main → правка → pnpm check (зелёный) → PR
```

- **Ветка от `main`.** В `main` напрямую не коммитим.
- **Перед пушем — `pnpm check`** (это `lint && typecheck && test`). Те же проверки гоняет CI,
  поэтому красный `check` = красный CI.
- **Куда класть код** (подробно — [`../CLAUDE.md`](../CLAUDE.md) › Конвенции):
  чистые функции → `app/utils/*` + юнит-тесты; реактивная логика → `app/composables/*`;
  UI → компоненты. Данные из API рендерим только через `{{ }}`, никакого `v-html`.
- **UI-правки сверяем с документацией Bitrix24 UI** (`b24ui`).
- **Тексты для пользователя** — по-русски, простыми словами. Если ожидается нажатие — пишем
  про нажатие. В ошибке должно быть понятно: **где** произошло, **что** случилось,
  **что делать дальше**.
- **Комментарии и JSDoc в коде** — по-английски; `.md` и пользовательский текст — по-русски.

### Команды

```bash
pnpm dev          # дев-сервер
pnpm check        # lint + typecheck + test — гонять перед пушем
pnpm test         # только тесты (быстро: pnpm test --project unit)
pnpm generate     # сборка статики (то же гоняют CI и Dockerfile)
pnpm screenshots  # скриншоты роут×вьюпорт×тема (см. §2.2)
pnpm og:snapshot  # регенерация public/og.png из scripts/og.svg
pnpm rates:snapshot # регенерация public/rates-fallback.json
```

## 2. Проверка

Три уровня. Первые два — обязательны всегда, третий — перед релизом в Маркет.

### 2.1. Автотесты (`pnpm check`)

Покрыто: чистые функции (`app/utils/*`), конфиг, директива автоповтора, composables и
страницы (проект `nuxt` через `@nuxt/test-utils`), паритет локалей, штампы документов,
список зон в CSP. Портал Bitrix24 и живая Метрика в автотестах **не** проверяются — SDK
замокан.

### 2.2. Глазами (`pnpm screenshots`)

Дев-харнесс: снимает роут × вьюпорт × тему (12 PNG) уже установленным Chromium. Baseline и
diff'а нет — это «свериться глазами», поэтому **в CI не гоняется** и прод не трогает.
Сначала поднять `pnpm dev`, потом запускать.

Что смотреть: главная (светлая/тёмная, 375/1280), виджет `/widget/converter` (компактная
раскладка под узкий iframe), `/install` (вне портала снимок ловит экран мок-прогресса
«Application installation / Connecting to Bitrix24…» + свёрнутую «Diagnostics» — редирект
на `/` происходит позже и в кадр не попадает).

### 2.3. Руками — то, что автотесты не могут

Нужен реальный портал Bitrix24 и валидный счётчик Метрики.

**Критично для релиза** (блокеры публикации):

| # | Что | Ожидание |
|---|---|---|
| К1 | Открыть `/` | Строки валют заполнены, есть дата «на ДД.ММ.ГГГГ» |
| К2 | Ввести сумму в BYN и в USD | Остальные валюты пересчитались в обе стороны |
| К3 | Виджет в чате → «Вставить в чат» | В поле ввода чата вставлена **пропись** |
| К4 | Установка приложения в портал | Прогресс → `placement.bind` → успех, без белого экрана |
| К5 | `make prod-smoke-external` | `200`, валидный TLS |

**Важное, но не блокирующее:**

- *Конвертер:* удержание +/− (автоповтор, кламп в `[0, MAX]`), копирование строки (в буфере
  чистое число с точкой), пропись BYN/RUB, переключатель регистра «аб/Аб», формула и метка
  квартала, обновление курсов, пустое поле, ноль и максимум, мусорный ввод.
- *Ошибки:* открыть `/` без сети → красный блок с понятным текстом, без падения; кэш в
  пределах 12 ч не ходит в сеть; помесячная валюта (RSD) может быть пустой — страница жива;
  протухший кэш (>12 ч) перезапрашивается.
- *Темы и адаптив:* переключатель темы сохраняется между визитами без FOUC; авто-тема по
  системной; 375px без горизонтального скролла; Tab-навигация и скринридер (`aria-label`,
  `aria-live` на «Спасибо за отзыв»).
- *Промо:* карточка Маркета видна standalone и **скрыта** в портале; custom-dev карточка
  видна всегда; QR по удержанию.
- *Виджет:* рендер в панели над полем ввода, регистр «аб/Аб», копирование (кроме мобильного
  приложения — там нет Clipboard API), ошибка курсов без падения, отсутствие горизонтальной
  полосы в узком попапе.
- *Установка:* имя виджета на 2–3 языках портала, повторная установка без дублей привязок,
  сбой установки показывает кнопку повтора, `/install` вне портала → редирект на `/`.
- *Dual-mode главной в портале:* заголовок фрейма выставлен, фрейм подгоняется под контент,
  блок «Помог курс?» скрыт.
- *Цели Метрики* (только standalone, смотреть в отчёте Метрики): `rates_load_failed`,
  `rates_monthly_missing`, `rates_fallback_used`, `converter_helpful_yes/_no`,
  `market_card_click`, `market_qr_reveal`, `custom_dev_click`, `custom_dev_qr_reveal`,
  `web_vitals_*`. Полный список и инвариант приватности — [`PROJECT_MAP.md`](PROJECT_MAP.md) §4.
- *Прод-дым:* нет CSP-ошибок в консоли; в подвале «сборка `<sha>`» ведёт на актуальный коммит.

## 3. PR, ревью и мерж

1. **PR в `main`.** В теле — проблема и что сделано, ссылки на issue (`Closes #N`).
2. **Проверяющие.** Каждый PR смотрят несколько независимых ревьюеров (для кода — до 5:
   корректность, тесты, безопасность и приватность, архитектура, тех-директор; для доков —
   точность против кода, полнота, консистентность).
   - **Adversarial:** ревьюер ищет дыру, а не подтверждает. Вердикт —
     **БЛОКЕРЫ / ЗАМЕЧАНИЯ / ЧИСТО**.
   - **Формат находки:** кто · что · почему · как исправить.
   - **Устранение:** блокеры обязательны; замечания — устранить либо обосновать отказ.
     После правок — перепроверка.
   - Смысл не в зелёной галочке: например, фикс горизонтального скролла виджета оказался
     в родительском layout, а не там, где правил автор — это нашли именно ревьюеры.
3. **Мерж — только когда `ci` и `docker-build` зелёные.** Метод — squash, в заголовке номер PR.
   Решение о мерже за владельцем; агент доводит PR до зелёного CI и мержит только по явному
   разрешению.
4. **Отдельного hotfix-пути нет** — прод-инцидент идёт тем же циклом; быстрый выход — откат (§7.2).

### Штамп ревью документов

Каждый `.md` в корне и в `docs/` несёт строку `> Last reviewed: YYYY-MM-DD` блок-цитатой
сразу под заголовком H1. Ключ `Last reviewed` — всегда по-английски (технический маркер,
ищется одним grep). Дату бампим только при содержательном изменении, не при косметике.
Наличие штампа проверяет `tests/mdReviewStamp.test.ts` (`reporting-kit/` исключён — у него
свой процесс).

## 4. Сборка и деплой

```
push в main
  └─ GitHub Actions job `ci` (зелёный?) → job `deploy`
       └─ docker build → push в ghcr.io/bx-shef/currency-converter:latest + :sha-<коммит>
            └─ Watchtower на сервере (~5 мин) подхватывает latest
                 └─ контейнер пересоздаётся за общим nginx-proxy (TLS Let's Encrypt)
```

- **CI** (`.github/workflows/ci.yml`): job `ci` (install → `nuxi prepare` → lint → test →
  typecheck → `nuxt generate`) на push и PR; job `docker-build` на PR (собирает прод-образ
  **без** push — ловит поломку Dockerfile до прода, работает и на Dependabot-PR).
- **Красный `ci` блокирует деплой** — образ не попадёт в GHCR.
- **Теги:** `latest` (его слушает Watchtower) + `sha-<коммит>` (immutable, нужен для отката).
- Два быстрых пуша в `main` сериализуются через `concurrency` на deploy-джобе — in-flight push
  не отменяется, полу-запушенный тег хуже ожидания.

### Что собирается в образ

Прод-образ — `nginxinc/nginx-unprivileged` (non-root, слушает `:8080`). Сборка **валится**,
если что-то из этого не сошлось:

- CSP-хэши не подставлены (плейсхолдер `__CSP_SCRIPT_HASHES__` остался в `nginx.conf`);
- `nginx -t` не проходит;
- `public/og.png` не попал в вывод.

CSP отдаётся **без** `script-src 'unsafe-inline'`: два inline-скрипта Nuxt разрешаются по
sha256-хэшам, которые `scripts/csp-hashes.mjs` считает из собранного HTML. **Любой новый
inline-скрипт без `src` сломает страницу** — выносить в `public/*.js` (как Яндекс.Метрику).

## 5. Установка в портал Bitrix24

Приложение работает в двух режимах: обычный сайт и iframe внутри портала.

1. Портал открывает `/install` (**POST**, поэтому в nginx стоит `error_page 405 =200 $uri;` —
   иначе белый экран «405 Not Allowed»).
2. `/install`: `init` → чистка старых привязок → `placement.bind` плейсмента `IM_TEXTAREA`
   (панель над полем ввода чата) на обработчик `/widget/converter` → `installFinish`.
   Имя виджета берётся из `app.title` **всех** локалей в момент установки.
3. Дальше пользователь открывает виджет в чате и жмёт «Вставить в чат» —
   уходит `im:setImTextareaContent` в поле ввода.

Требования к CSP: `frame-ancestors` и `connect-src` в `nginx.conf` должны разрешать облачные
домены Б24 (`*.bitrix24.<зона>`, ~22 зоны). Список **зеркалится** между двумя директивами,
инвариант проверяет `tests/nginxCsp.test.ts`. Синхронизируется вручную — Б24 добавляет
регионы; **self-hosted порталы на своём домене добавляют себя сами**, иначе iframe и REST падают.

Полный install-flow автотестами не проверить (нужен портал) — только руками, см. §2.3 К3–К4.

## 6. Публикация в Маркете Bitrix24

Цель гейтов — не выпустить в Маркет то, что сломано в портале.

| # | Гейт | Как проверить |
|---|---|---|
| 1 | Автопроверки зелёные | `pnpm check` |
| 2 | Прод задеплоен и жив | `make prod-smoke-external` → `200` |
| 3 | Визуальная проверка | `pnpm screenshots`, просмотреть `/`, `/widget/converter`, `/install` в свете и тьме на 375/1280 |
| 4 | Ручной прогон в портале | §2.3 К3–К4: установка → bind `IM_TEXTAREA` → «Вставить в чат» → dual-mode главной |
| 5 | Версия сборки | в подвале «сборка `<sha>`» ведёт на актуальный коммит |
| 6 | `MARKETPLACE_URL` актуален | указывает на опубликованный листинг |
| 7 | Имя приложения на всех языках | `app.title` во всех `i18n/locales/*.json` |
| 8 | CSP разрешает облако Б24 | `frame-ancestors`/`connect-src` в `nginx.conf` |
| 9 | Приватность актуальна | [`PROJECT_MAP.md`](PROJECT_MAP.md) §4 — для карточки Маркета и вопросов о данных |

**Порядок:** смержить в `main` → дождаться авто-деплоя (~5 мин) или `make prod-redeploy` →
пройти гейты 1–9 → обновить листинг в кабинете разработчика (описание, скриншоты, версия) →
после публикации ещё раз пройти гейт 4, но уже установкой **из Маркета** на тестовом портале.

### Случаи, когда порталам нужна переустановка

- **Смена `app.title`** — имя чип-плейсмента фиксируется в момент установки.
- **Смена домена / `NUXT_PUBLIC_SITE_URL`** — HANDLER абсолютный, нужна пересборка образа
  и переустановка.
- **Major-бамп `@bitrix24/b24jssdk`** — рантайм SDK автотесты не покрывают, обязателен
  ручной прогон в реальном портале.

### Известные ограничения (задокументированы, публикацию не блокируют)

Мобильное приложение Б24: виджет view-only, «Вставить в чат» скрыт (#124). Ввод разделителя
точкой в поле суммы (#136) и подстройка под ресайз фрейма (#138) — поведение портала и
компонента, отслеживается отдельно. Подробности — [`FUTURE.md`](FUTURE.md).

## 7. Эксплуатация

### 7.1. Регулярный мониторинг

| Что | Как проверить | Норма |
|---|---|---|
| Доступность снаружи | `make prod-smoke-external` | `200`, валидный TLS |
| Контейнер жив | `docker ps` | `Up (healthy)` |
| TLS-сертификат | `echo \| openssl s_client -connect $DOMAIN:443 2>/dev/null \| openssl x509 -noout -enddate` | обновить, если **< 14 дней** |
| Свежесть деплоя | `docker inspect currency-converter --format '{{.Image}}'` | sha совпадает с последним коммитом `main` |
| Watchtower | `docker logs watchtower --tail 20` | периодические «Session done» |
| Диск | `docker system df` | логи капнуты (10 МБ × 3); при росте — `docker image prune -f` |

TLS продлевается автоматически (acme-companion); руками вмешиваемся, только если продление
**не** происходит.

**Здоровье приложения** видно по целям Метрики (только standalone): рост `rates_load_failed`
= проблема с `api.nbrb.by`; `rates_fallback_used` = API НБ РБ лежит и людям показывается
снапшот; `web_vitals_*` = производительность.

### 7.2. Обновление и откат

- **Обычное обновление** — автоматически: мерж в `main` → CI пушит образ → Watchtower
  подхватывает за ~5 мин. Форсировать: `make prod-redeploy` (pull + up + prune + smoke).
- **Откат:** `make prod-rollback TAG=sha-<коммит>` — поднимает конкретный immutable-образ и
  гоняет smoke. Watchtower такой тег не трогает. Вернуть авто-обновление — `make prod-redeploy`.
- **После отката или редеплоя — обязательно `make prod-smoke-external`** (проверяет весь путь
  DNS → nginx-proxy → TLS → приложение, чего внутренний smoke не ловит).

### 7.3. Инциденты

| Симптом | Первая гипотеза | Что делать |
|---|---|---|
| `502` от nginx-proxy | контейнер не в той docker-сети, либо `VIRTUAL_PORT` ≠ порт nginx в образе (`8080`) | `docker network inspect <сеть>` — там оба контейнера? Затем перекачать `docker-compose.prod.yml` (`curl -fsSLO`) и `make prod-up`: частая первопричина — устаревший compose на сервере |
| Белый экран в портале, `405` или Mixed-Content | пропал `error_page 405 =200 $uri;` или `absolute_redirect off;` | проверить `nginx.conf` в образе, пересобрать |
| TLS не выдан или не продлён | DNS не резолвится / rate-limit Let's Encrypt | `docker logs <acme-companion>`; `dig +short $DOMAIN`; проверить `LETSENCRYPT_EMAIL` |
| Watchtower не обновляет | нет `DOCKER_API_VERSION` или метки на контейнере | `docker logs watchtower`; метка `com.centurylinklabs.watchtower.enable=true` |
| Курсы не грузятся у всех | `api.nbrb.by` недоступен | Внешняя проблема НБ РБ. Холодную загрузку спасает снапшот `public/rates-fallback.json` (бейдж «резервная копия»), вернувшихся — кэш. Снапшот статичен, обновляется `pnpm rates:snapshot` |
| Сборка или деплой красные | см. Actions: `ci` → `deploy` | Частое: нет lockfile для кэша; мажорный бамп Node (corepack); пропавший OG-ассет |

**Логи:** приложение — `make logs`; Watchtower — `docker logs watchtower`; TLS —
`docker logs <acme-companion>`. Ротация json-file 10 МБ × 3, диск не забьётся.

### 7.4. Что не трогать без нужды

- **Пины образов** watchtower / nginx-proxy / acme-companion — у них доступ к `docker.sock`,
  плавающий `latest` там = вектор supply-chain атаки.
- **SHA-пины сторонних GitHub Actions** в `ci.yml` — их обновляет Dependabot вместе с
  комментарием версии.
- **`.env.prod` на сервере** — не в git. При смене домена или портов перекачать compose и
  `make prod-up`.

## 8. Грабли, за которые уже платили

Коротко, чтобы не наступить второй раз. Полные разборы — в истории PR и issue.

| # | Грабля | Как правильно |
|---|---|---|
| 1 | Имя docker-сети nginx-proxy на серверах разное (`proxy-net`, `nginx-proxy`, `webproxy`) | Не угадывать — смотреть `docker network ls`; в compose помечать `external: true`. Не совпало → 502 |
| 2 | `default`-сеть в compose приложения | Убрать: без явного `networks:` контейнер окажется в двух сетях |
| 3 | Watchtower по умолчанию обновляет **все** контейнеры хоста | `--label-enable` + метка на нашем сервисе |
| 4 | Watchtower молча не работает | Нужен `DOCKER_API_VERSION=1.47`: по умолчанию он говорит на API 1.25, а demon 24+ требует ≥1.44 |
| 5 | Публичные переменные Nuxt через `environment:` в compose | Не сработают — они запекаются при сборке, нужны build-args (§0.1) |
| 6 | non-root nginx не может слушать `:80` | `listen 8080` + `VIRTUAL_PORT: 8080`; иначе 502 |
| 7 | За TLS-терминирующим прокси внутренний nginx строит редиректы со своим портом | `absolute_redirect off;` — иначе `Location: http://host:8080/...`, в HTTPS-iframe это Mixed-Content и виджет молча не грузится |
| 8 | Б24 открывает обработчик через **POST**, статика отвечает `405` | `error_page 405 =200 $uri;` — странице не нужно тело запроса, контекст портала приходит через `window.name` и postMessage |
| 9 | CSP без `unsafe-inline` ломается на любом новом inline-скрипте | Выносить скрипты в `public/*.js`; хэши считает `scripts/csp-hashes.mjs`, ассерт в Dockerfile валит сборку |
| 10 | json-file логи без лимита забивают диск | `max-size: 10m`, `max-file: 3` |
| 11 | Мажорный бамп Node ломает сборку | Node 25+ выкинул corepack из образов (`exit 127`) — держим базу на LTS `node:22-alpine`, Dependabot на мажоры Node не прыгает |
| 12 | Нет lockfile → CI-кэш падает | `pnpm-lock.yaml` закоммичен до включения `cache: 'pnpm'` |
| 13 | OG-картинка требовала тяжёлый inkscape в образе | `public/og.png` закоммичен, регенерация локально `pnpm og:snapshot` |
| 14 | DNS не готов до первого старта acme-companion | Let's Encrypt закеширует rate-limit на час — сначала DNS, потом запуск |
